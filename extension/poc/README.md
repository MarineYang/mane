# PoC — 유튜브 이중자막 (로컬 테스트용)

파이프라인 검증용 최소 구현. **빌드 도구 없이 그대로 로드**해서 테스트할 수 있도록 순수 JS로 작성했다. (프로덕션 확장은 TypeScript로 `extension/src/`에 별도 구현 예정 — [ADR 0002](../../docs/adr/0002-site-adapter-and-youtube-first.md))

## 로드 방법

1. Chrome 주소창에 `chrome://extensions` 입력
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** 클릭
4. 이 폴더(`extension/poc`) 선택
5. **일본어 자막이 있는 유튜브 영상**을 연다 (아래 "테스트 영상 고르기" 참고)

## 확인할 것

- 영상 하단에 **일본어(흰색, 큰 글씨) + 한국어(노란색, 작은 글씨)** 2줄이 뜨는가
- **배속 변경 / 앞뒤 탐색(seek) / 일시정지** 후에도 자막 싱크가 맞는가
- 다른 영상으로 이동(SPA 전환)했을 때 이전 자막이 남지 않고 새로 로드되는가
- 전체화면에서도 정상 표시되는가

**Alt + J** 로 이중자막 표시를 껐다 켤 수 있다.

진행 상황은 DevTools 콘솔(F12)에 `[langflix-jp]` 로 찍힌다:

```
[langflix-jp] 자막 로드 완료 — 일본어 812줄 / 한국어 812줄 {jaIsAutoGenerated: false, koSource: "youtube-auto-translate"}
```

- `jaIsAutoGenerated: true` → 자동생성 자막이라 정확도가 떨어질 수 있음
- `koSource` → `native`(정식 한국어 자막) 또는 `youtube-auto-translate`(유튜브 자동 번역)

## 테스트 영상 고르기

**일본어 정식 자막(자동생성 아님)이 달린 일반 영상**으로 먼저 검증할 것. 유튜브 플레이어의 설정(⚙) → 자막 목록에 `일본어`가 있고 `일본어(자동 생성됨)`이 아니면 정식 자막이다.

쇼츠(`youtube.com/shorts/...`)도 같은 코드로 동작하지만, 정식 자막 없이 자동생성에 의존하는 경우가 많아 품질 편차가 크다. **일반 영상으로 먼저 확인한 뒤** 쇼츠를 테스트하는 것을 권장.

## 동작 방식

```
injected.js  (페이지 컨텍스트)          content.js  (격리 환경)
─────────────────────────────          ──────────────────────────
player response 가로채기                  ← CUES 메시지 수신
  → captionTracks 추출                    → 오버레이 DOM 생성/재부착
  → timedtext(json3) 다운로드             → currentTime 기준 이진 탐색
  → cue 배열로 정규화 ────────────────▶   → 매 프레임 2줄 렌더
```

- **일본어 라인**: 영상의 일본어 자막 트랙 (정식 자막 우선, 없으면 자동생성)
- **한국어 라인**: 정식 한국어 트랙이 있으면 그것, 없으면 유튜브 자동 번역

## PoC의 한계 (의도적으로 뺀 것)

프로덕션에서는 아래가 모두 교체·추가된다.

| 항목 | PoC | 프로덕션 |
|---|---|---|
| 한국어 번역 | 유튜브 자동 번역 | 백엔드 LLM 번역 + Redis 캐시 |
| 표현 하이라이트 | **없음** | NLP 형태소 분석 + JLPT 레벨 강조 |
| 뜻풀이 툴팁 | **없음** | JMdict 사전 + 후리가나 |
| 표현 저장 | **없음** | 백엔드 동기화 → 앱에서 복습 |
| 넷플릭스 | **없음** | NetflixAdapter 추가 |
| 언어 | 순수 JS, 빌드 없음 | TypeScript + 번들러 |

## 다음 단계
