# ADR 0002 — 크롬 확장의 사이트 어댑터 구조 및 유튜브 PoC 선행

- **상태**: 승인됨 (2026-07-22)
- **관련**: [ADR 0001](0001-core-decisions.md), `docs/architecture.md` §1

## 맥락

ADR 0001에서 MVP를 "넷플릭스 확장 우선"으로 정했다. 그런데 로컬에서 먼저 동작을 검증하려면 넷플릭스는 진입 장벽이 크다.

- 유료 구독이 있어야 재생 자체가 가능
- 플레이어가 자막 렌더링·상태·생명주기를 내부에서 강하게 통제(오버레이를 덮어쓰거나 재빌드)
- 영상 DRM 환경이라 개발·디버깅이 까다로움

반면 유튜브는 계정 없이 재생되고, 캡션(timedtext) 접근이 상대적으로 개방적이며, 플레이어 DOM을 다루기 쉽다.

## 결정

**1. 확장을 `SubtitleSource` 사이트 어댑터 구조로 설계한다.**

확장 코드의 대부분(오버레이 렌더러, 번역 클라이언트, NLP 하이라이트, 뜻풀이 툴팁, 표현 저장/동기화)은 사이트와 무관하다. 사이트별로 갈리는 것은 **cue 취득 방식**과 **재생 시각(`currentTime`) 접근**뿐이므로, 이 둘만 인터페이스 뒤로 분리한다.

```
SubtitleSource (interface)
  ├─ YouTubeAdapter   ← youtube.com/watch + youtube.com/shorts
  └─ NetflixAdapter   ← netflix.com/watch
```

**2. 유튜브 어댑터로 PoC를 선행한다.**

파이프라인 전체(cue → 일→한 번역 → 형태소/후리가나/JLPT 하이라이트 → 표현 저장)를 유튜브에서 먼저 검증하고, 검증된 공통 레이어에 `NetflixAdapter`만 갈아끼운다. 넷플릭스에서 겪을 "자막 취득 + 싱크" 난이도를 초기 단계에서 분리해내는 것이 목적이다.

## 근거

- 어댑터 분리 비용은 거의 없는데(인터페이스 1개), 넷플릭스 난제를 나머지 개발과 **분리**할 수 있다.
- 넷플릭스 구독 없이도 개발이 진행된다.
- 쇼츠(`youtube.com/shorts/...`)도 같은 어댑터로 커버되어 Phase 2 준비가 겸사겸사 된다.

## 영향

- **로드맵 변경 아님.** Phase 2의 "유튜브 쇼츠 **인앱**(모바일 앱) 플레이어"는 그대로 유지된다. 확장의 유튜브 지원은 별개 산출물이며, 추후 PC 정식 기능으로 승격할 수 있다.
- MVP 확장 작업 순서가 "① 유튜브 어댑터 PoC → ② 넷플릭스 어댑터 추가"로 명시된다.

## 주의

쇼츠는 정식 자막 없이 **자동생성 자막에 의존하는 경우가 많아** 품질 편차가 크다. 초기 검증은 **일본어 자막이 제대로 달린 일반 영상**으로 하고, 쇼츠는 그다음에 붙인다.
